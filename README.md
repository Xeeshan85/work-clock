# WorkClock

WorkClock is a local work-hours stopwatch for Kubuntu. The big display behaves like a stopwatch. Each start and stop is saved immediately, and **Submit day** writes that date into History.

Nothing leaves the computer. There is no account and no network access.

## Install

These steps need to be done once. After that, start WorkClock from the application menu.

```bash
sudo apt install python3-venv python3-pip
git clone <your repository url>
cd workclock
chmod +x install.sh uninstall.sh
./install.sh
```

Search for **WorkClock** in the application launcher, or pin it to the desktop. You do not need a terminal to start it again.

Upgrade later by pulling the new code and running `./install.sh` again. Your log stays in `~/.local/share/workclock/workclock.db`.

Remove the app with `./uninstall.sh`. That deletes the menu entry and leaves the database in place.

## Global shortcut

WorkClock does not grab the keyboard itself. KDE binds the shortcut:

1. Open **System Settings → Keyboard → Shortcuts** (Plasma 6: **System Settings → Shortcuts**).
2. Choose **Add Application…** (or the **+** button) and pick **WorkClock**.
3. Bind **Start or Stop Timer**.

That menu action runs `workclock --toggle`. If WorkClock is already open, the running instance toggles. If it is not open, it starts and toggles.

## In the app

- **Space** starts or stops the stopwatch. **L** records a lap. **Ctrl+Enter** submits today. Those keys stay out of the way while you are typing, including in the project box.
- The **⇅** button at the top right of the stopwatch swaps the big time and the smaller one, so the day total can be the large clock.
- **Settings** on the Timer page chooses the clock: hours and minutes (a flip clock), with seconds, or with centiseconds. It also has the idle prompt (off by default), daily target, reminders, starting in the tray, and launching at login.
- **Countdown** is the other page on Timer. Set a duration, start it, and it counts down on a dial. At zero it rings, logs the session, and stops. Stopping early logs only the time that actually ran.
- **Add time** puts missed minutes on the running stopwatch, or records them as finished time.
- Closing the window hides WorkClock in the system tray. **Quit** in the tray menu exits.
- A second submit on the same date merges into that day's total and keeps a separate log, with its own start, finish, and note.
- History has **Submit day** and **Reopen day**. Reopen unlocks a day; Submit day locks it again. After a submit, that day is selected so its log shows immediately.
- History charts cover 7 days, 14 days, the current month, and all time (one point per month).

## Publish on Flathub

The store behind KDE Discover and GNOME Software is [Flathub](https://flathub.org). Kubuntu's Discover can install from it. The Snap Store is a separate Ubuntu catalog; for this Qt app, publish to Flathub.

Flathub's own guides are the checklist that reviewers use:

- [Requirements](https://docs.flathub.org/docs/for-app-authors/requirements)
- [Submission](https://docs.flathub.org/docs/for-app-authors/submission)
- [MetaInfo guidelines](https://docs.flathub.org/docs/for-app-authors/metainfo-guidelines)

Do this before opening a submission:

1. Add a `LICENSE` file. You choose the license. Flathub will not take the app without one.
2. The public repository is [github.com/Xeeshan85/work-clock](https://github.com/Xeeshan85/work-clock). Tag a release such as `v1.0.0` only after the `LICENSE` file is in that tag. The application id has to match the repository: `io.github.Xeeshan85.work-clock`.
3. Use the app yourself for a while and keep a real commit history. Flathub rejects projects that have only just appeared.
4. Take screenshots of the stopwatch, the countdown, and History. The MetaInfo file has to include them.
5. Turn on two-factor authentication for your GitHub account. Flathub asks for it when they give you the app repository.

Write the Flatpak manifest yourself. Flathub does not accept a manifest that was generated by an AI assistant, and undisclosed AI-written parts of the app can get a submission rejected. If an assistant wrote code or docs in this repository, say so in the pull request: what it touched, and how much. You still need to be able to maintain the app.

The manifest should use a current `org.kde.Platform` runtime (not an end-of-life branch). That runtime already provides PySide6, so the build installs this project with `pip3 install --prefix=/app --no-deps .` from the git tag. Confirm the import inside the SDK before you rely on that. Give the sandbox what the window needs:

- `--share=ipc`
- `--socket=fallback-x11` and `--socket=wayland`
- `--device=dri`
- `--talk-name=org.freedesktop.Notifications`
- `--talk-name=org.kde.StatusNotifierWatcher` so the tray icon works
- `--talk-name=org.freedesktop.ScreenSaver` so the idle prompt can ask how long the session has been idle

Inside Flatpak the database lives in the sandbox home, not in your current `~/.local/share/workclock/`. Export JSON from the copy you use now and import it after installing the store build. "Launch when I log in" writes an autostart file inside the sandbox, so it will not start the host session unless a reviewer accepts a narrower permission for that. The timer, tray, and history do not need it.

Build and run it locally with `flatpak-builder`, then check the manifest and MetaInfo with `flatpak-builder-lint`. When that is clean, fork [flathub/flathub](https://github.com/flathub/flathub), branch from `new-pr`, and open a pull request whose base is `new-pr`. Title it `Add io.github.Xeeshan85.work-clock`. The manifest file name is the application id. After it is accepted you get write access to a new repository under the Flathub organization; later updates go there and do not repeat this review.

On a Kubuntu machine, Discover shows the app once Flathub is enabled under Settings → Flatpak. Searching for WorkClock is enough to install it.
